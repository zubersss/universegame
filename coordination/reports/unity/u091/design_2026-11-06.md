## Residency map (summary)
terrain/earth/snow is counted under planet_earth after Mars entry because Mars loads that sheet itself. It is not the SceneDirector preload, and Residency is not attributing a session handle to planet_earth.

Mars's material list includes TileId.Snow (C:\dev\universegame\Assets\_Game\Code\Runtime\Terrain\TerrainStreamer.cs:161, comment at :160: Mars's CO2 frost uses Snow). TileId 5 maps to ArtKeys.Terrain.EarthSnow = "terrain/earth/snow" (C:\dev\universegame\Assets\_Game\Code\Runtime\Terrain\TerrainTiles.cs:9 and :23; C:\dev\universegame\Assets\_Game\Code\Runtime\Art\ArtKeys.cs:40). There is no terrain/mars/snow or frost sheet. When Mars's TerrainStreamer.Begin runs (TerrainStreamer.cs:71-72), TerrainTileSet.Load (C:\dev\universegame\Assets\_Game\Code\Runtime\Terrain\TerrainTileSet.cs:49) calls ArtLoad.Asset("terrain/earth/snow"). That goes to Residency.Track(key) and GroupOf: the "terrain" case returns "planet_" plus the second segment, which is "planet_earth" (C:\dev\universegame\Assets\_Game\Code\Runtime\Perf\Residency.cs:20 and :118-119). The asset really is in the planet_earth Addressables group (C:\dev\universegame\Assets\AddressableAssetsData\AssetGroups\planet_earth.asset:28-29, BundleMode 0 = PackTogether). So the one remaining planet_earth holder is Mars's own live TileSet, and it is released when Mars unloads (TerrainStreamer.cs:417 and :420, TerrainTileSet.cs:159). It is a planet attribution problem, not a leak.

Why it is not the preload: ArtLoad.Session tracks the handle with group "session" (C:\dev\universegame\Assets\_Game\Code\Runtime\Art\ArtLoad.cs:55). Because the key argument is null, the key is also stored as "session" (Residency.cs:25). PlanetOf("session") returns null (Residency.cs:88). So a session entry can never appear in CountPlanet("planet_earth") or in Holders("planet_earth") as "terrain/earth/snow".

The probe logs prove it. In C:\dev\universegame\logs\memory_probe_20261106_164339.jsonl and C:\dev\universegame\logs\memory_probe_20261106_163535.jsonl, the Space leg shows prevGroup planet_earth, prevHandles 0, holders "none", and planet_earth is not among the resident groups. On the Mars leg planet_earth is resident again, with 1 handle: terrain/earth/snow. The session preload did not change between those two legs, so the count came back with Mars's own load.

The earlier count of 7 fits the same explanation. Before commit 96112df, Prune dropped an entry only when its handle was no longer valid (Residency.cs:129-133). The session preload keeps the shared Addressables operation alive, so Earth's six released TileSet handles stayed valid. That gives 6 Earth entries plus Mars's snow entry, 7 in all. The 11:13 PlayMode run shows the same pattern: snow x20 against x18 for the other Earth sheets (C:\dev\universegame\coordination\reports\unity\tests_2026-11-06.md:54). Once 96112df routed every release through ArtLoad.Release and Untrack (ArtLoad.cs:42-47, Residency.cs:29-33), only Mars's live handle is left.

The current status note is wrong. C:\dev\universegame\coordination\status\UNITY_STATUS.md:4 blames the session preload "under the planet group". Keying the preload by planet and releasing it on transition would not change this count. ResidencyTests will keep failing at C:\dev\universegame\Assets\_Game\Tests\Unit\Play\ResidencyTests.cs:121-122 until Mars stops loading an Earth-addressed sheet, or until the group/attribution rule changes. Options: give Mars its own frost key, move the snow sheet to a shared group in both ArtRules.GroupFor and Residency.GroupOf, or treat a planet's own TileSet loads as that planet's.

Accounting model:
- ArtLoad.Asset(key) tracks under GroupOf(key) (ArtLoad.cs:14-19).
- ArtLoad.Asset(location, key) tracks under GroupOf of the key passed in (ArtLoad.cs:22-27).
- ArtLoad.Assets(label, group) tracks under the explicit group, with the label as key (ArtLoad.cs:30-35).
- ArtLoad.Session(key) tracks under "session" with key "session" (ArtLoad.cs:52-57).
- ArtLoad.Release returns early if the handle is invalid, otherwise Untracks it and calls Addressables.Release (ArtLoad.cs:42-47).
- Untrack removes the last entry whose handle is Equal (Residency.cs:29-33). Equal means same operation and version, and Addressables gives every holder of the same key and type the same cached operation and version.
- Count, CountPlanet, Holders, ResidentGroups and OnlyPlanet all call Prune first.
- PlanetOf maps "planet_<id>" and "planet_<id>_*" to a planet for every PlanetId. Anything else (session, common, ui, icons, space, planet_space, planet_waystation, planet_warden, planet_rig) maps to null (Residency.cs:86-95).
- GroupOf (Residency.cs:109-127) is meant to mirror ArtRules.GroupFor but has no "flora" case (C:\dev\universegame\Assets\_Game\Code\Editor\ArtRules.cs:110), so flora/<planet>/* is counted as "common".

Persistent holders that outlive a PlanetSide unload, all by design and none planet-scoped:
- TerrainTileSet.kept (18 session terrain sheets for Earth, Mars, Mercury and Venus)
- FilmFeature's three session overlay textures
- FxSheet.cache
- ItemIcons
- MenuController title art
- SpaceWorld, SpaceBackdrop, DockingBay and Waystation (Space scene)
- ArtMaterials.active block textures (Resources, not Addressables)
- TerrainBlockPalette static arrays

Everything else (CreatureDirector, PoiPlacer, StageLayers, DepthBands, PlanetBackdrop, ParallaxLayers, FloraRigs, GroundStrip, SpriteCharacterView, ModelView and ModelSwap instances, PlayerView, ShipLegsView, RigToolView, DustStorm, BaseBuilder, CataloguePanel) is a PlanetSide instance that releases in OnDestroy or Clear. The DontDestroyOnLoad objects (MemoryProbe, PostFx) hold no art. No file was edited.
